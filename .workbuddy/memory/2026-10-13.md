## dsh 插件开发的关键事实（踩坑记录）

- dsh 内核源码在 `D:\DSHV2\DSH Desktop\resources\app\node_modules\@deepseek-ai\`。
- 插件契约：`export const inject = [...]` + `export function apply(ctx, config)`，
  用 `ctx.effect(() => disposer, 'label')` 管生命周期。参考 `D:\TauriTavern\dsh-tavern-mode`。
- **Host→浏览器推送只能走 webServer + SSE**（`ctx.webServer.register({kind:'prefix', path, handler})`，
  handler 签名 `(req, res)` 就是 node:http 那套）。**Typert 第三方插件用不了**，它要构建期产物。
- 客户端插件：`window.__ModuleLoader__.load({ id, factory(require){ ... return { inject, apply } } })`，
  由 package.json 的 `dsh.client` 声明自动加载，**patch 里不要再 insert 一条**（会把浏览器代码当 host 插件 import）。
  客户端 URL 用文档相对路径（不带前导斜杠），跟内核 HMR 一致。
- 路由前缀别用 `/plugins`（客户端产物占了）。用 `/api/<包名>`。
- 插件装在 profile 时**解析不到 `@deepseek-ai/*`**（dsh 用自己的 internal loader 才行）。
  回退办法：从 `process.execPath` 推导 `<exe目录>/resources/app/node_modules/@deepseek-ai/<pkg>/lib/index.js`。
- `defineTool` 的 object schema **必须显式写 `additionalProperties`**，否则抛 JsonSchemaError。
- 动态上下文注入用 `ctx.systemPrompt.section({ name, order, text: () => string })`，
  `text` 可以是函数，每次组装时求值 —— 不用反复重新注册。`getSectionOrder('skills')` 取基准 order。
- 顶层 fiber 注册的工具对 agent 可见（`@deepseek-ai/dsh-tools` 本身就挂顶层）；
  `preset-cordis` 没有 restrict，不会过滤掉新工具。
- 事件名里**没有**「一轮回复结束」这类钩子；真要自动每轮朗读得 hook `agent/turn-stopping`（未采用）。

## MiMo TTS 的坑（重要）

**不能用 `fetch`（undici）调 MiMo**：keep-alive 连接被复用时，MiMo 边缘会在下一次请求约 10 秒处掐断
socket，报 `TypeError: terminated`（第一次总是成功，之后连续失败）。
改用 `node:https` + `new Agent({ keepAlive: false })`，连打 4 次全部成功。
单次合成耗时 7–17 秒，600KB–850KB WAV，工具超时要留够（默认 60s）。

API：`POST {base}/chat/completions`，header `api-key`，model `mimo-v2.5-tts-voicedesign`，
messages = [user: 音色描述, assistant: 要念的文本]，audio: `{format:'wav', optimize_text_preview:true}`。
返回 `choices[0].message.audio.data`（base64）。

dsh 自带的语音输入（`@deepseek-ai/dsh-experimental-voice-input-bundle`）**只有 STT 没有 TTS**，
且录音转写完即弃 —— 这就是 stt-tap 存在的原因。

## 追加：消息上的朗读按钮

client.js 新增 `conversation.chat.assistant-actions` slot 注册（`dsh-client-ui-message-feedback`
是同款入口的官方范例），每条助手消息的操作排里多了个喇叭按钮：点一下抓取该段文本 →
POST `/speak` → SSE 广播驱动播放。

关键事实：
- slot 组件只拿到 `{ messageId }`，**拿不到文本**。文本抓取靠 DOM：按钮在
  `[data-turn-tail]` 容器里，克隆后删掉所有 `[data-clock]`（操作排自己），剩下的
  textContent 就是可见正文。
- 按钮渲染位置是 `extraActions`（copy 之后、branch 之前），slot 体系没法塞到分支右边。
- 官方按钮样式可抄 `MessageIconActions.module.css`：28px 圆角透明按钮 +
  `--dsw-alias-label-tertiary` 色 + hover 变 `--dsw-alias-interactive-bg-hover`。
- 客户端验证办法（不用起 dsh）：mock `window.__ModuleLoader__` 和 `require('react')`
  后 import client.js，再 mock `ctx.slots` 调 apply，能确认 slot 注册。
  注意 apply 会启动 SSE 重试循环，测试进程不会自己退出。

## 追加 2：按钮不出现/无声的排查（16:54 重启后）

现象：host 全部正常（`/api/dsh-mimo-voice/status` 200、tap 挂上、日志无错），
